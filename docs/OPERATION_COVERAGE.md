# Operation coverage of the UI

Every operation type of BitShares core (`libraries/protocol/.../operations.hpp`, ids 0-77) against what the UI
does with it. Generated by reading the sources (not by running them), so a "yes" means the code for it exists.

- **Create**: some screen or action builds the operation (`add_type_operation(...)`, `ApplicationApi`, the
  SameT / credit / pool / order / ticket actions). "virtual" operations are made by the chain, never sent.
- **History line**: `Blockchain/OperationAnt.js` words the operation in account histories, proposals and (for the
  types without a component of their own) the block explorer's rows.
- **Detail**: `Blockchain/Transaction.tsx` has a table of its own for it in the block explorer; **no** here still shows
  a table of the operation's fields (`Blockchain/operations/GenericRows.tsx`), so nothing is hidden or left as a raw JSON tree.
- **Label**: `transaction.trxTypes.<name>` exists in the locale files.

bitsharesjs 6.0.3 (the version the UI depends on, the latest on npm) does not know operations 75-77.
`lib/chain/extraOperations.ts` registers them (serializers checked byte for byte against bitsharesjs's develop
branch; `app/index.js` imports it first); it leaves a name alone once the dependency knows it.
